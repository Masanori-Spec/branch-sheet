## Actual Freeplane producer

The workflow verifies the official Freeplane 1.13.3 ZIP, 71,889,782 bytes, SHA-256 `f1ac40ede94e0c47d0ca29fbfb2533fd41ced9e19d6a06abff78915a1214ba84`, release commit `3a76de18523993a55bf885190438bffef38662a5`. It also reads the installed version properties.

Under a disposable Xvfb/Openbox display and Java 17, the unmodified application imports the committed synthetic seed. Openbox uses its installed default configuration. Native windows are activated through the window manager; no security or scripting policy is altered. [xdotool's documentation](https://github.com/jordansissel/xdotool/blob/main/xdotool.pod) distinguishes this from raw input focus, which some applications may ignore. Ordinary keyboard/menu actions rename the root, save, close/reopen, rename X, move it between parents, create a new node Z, delete Y, and undo deletion to restore Y. Every saved transition must equal a fixed full tree of IDs, labels and parents before further actions proceed. The new Z ID is generated by Freeplane and recorded as a producer fact; all original IDs are literal fixed expectations. The changed map is reopened and saved again.

The disposable profile sets only ordinary startup preferences in `auto.properties` and a CopyIDAction keyboard shortcut in `accelerator.properties`. Both initial files and the effective accelerator file are retained as evidence. Before each native CopyID action, a fresh synthetic clipboard sentinel prevents stale contents from passing a repeated-ID check. The exact ID must then be returned. This verification is skipped only during cut/paste when it would overwrite the move clipboard; the complete saved-tree oracle checks that move. No user profile, imported script, real map, SecurityManager setting, security policy, or trusted-code installation path is modified. The native script never edits `.mm` XML to simulate a move.

The fixture has duplicate labels: X=Alpha under Products and Y=Alpha under Services. After editing, X=Beta under Services, Z=New under Products, and Y is absent. Retained native files and screenshots establish the producer behavior.

## Actual Calc consumer/editor

The workflow records the distro LibreOffice/UNO versions and installed packages. It uses a disposable profile and a local UNO pipe. Workbook loading requests NEVER_EXECUTE macros and NO_UPDATE links. The test inputs are synthetic tool outputs with no formulas. No recalculation API is called.

Actual Calc `setString` enters X’s `007`, `line1\nline2`, and `=1+1` values. Y has independent text including Japanese, a tab, and a literal SpreadsheetML escape-looking sequence. A native row sort reverses whole rows by ID. Calc saves through its `Calc Office Open XML` filter, closes and reopens the file. That actual Calc-saved file is the prior workbook supplied to the product.

The refreshed workbook is reopened in Calc. Its native cell strings, numeric reserved values, and cell types must equal the independent literal tables in `scripts/calc-native.py`. The unchanged refresh must reproduce identical workbook bytes. Restoring Y via the native map recovers its annotations. The 20,000-active/100-removed scale workbook is separately opened in Calc: both complete, independently specified unique ID sets and all 60,300 manual strings/types are checked, so duplicate native rows cannot satisfy the capacity oracle.

## Negative controls

Native Calc creates separate synthetic corruptions: changed reserved parent, swapped IDs, duplicate ID, stale metadata root, swapped X/Y annotation triples, and one corrupted annotation. Each retained actual input is checked against the exact intended fault. Reserved-field controls must fail product validation before export. Annotation edits are valid product inputs; the resulting actual native output must show precisely that intended fault and fail the independent literal fidelity oracle. This distinction prevents a misleading claim that normal manual edits are rejected.

Unit controls also reject malformed IDs, multiple roots, DTDs, clones, encryption, rich/typed/formula cores, numeric annotation cells, formulas, unknown columns/parts, external relationships and invalid ZIP sizes.

## Offline browser candidate gate

The standalone `dist/branchsheet.html` embeds only the pinned fflate, saxes and xmlchars JavaScript runtime, with full notices. No native application, server or network fetch is used by the app. It starts a fresh cancellable Worker for each explicitly selected map/workbook pair; revision guards discard superseded reads/results. Filtering and paging run in the Worker and return at most 50 rows. The preview shortens long strings; one dialog exposes the selected row’s complete values. Printing is limited to the current preview page and says so.

The hosted browser suite uses sandboxed Chromium on Ubuntu 22.04, opens the actual saved HTML through `file://`, and makes the context offline. It imports the same run’s actual Freeplane-produced maps and actual Calc-saved annotated workbook. It downloads initial, refreshed, repeated, filtered-scope, unchanged, restored and 20,000-row workbooks, plus a hash-bound review receipt. Complete byte equality to the independently native-tested CLI outputs is mandatory. Rejections, inert markup, delayed reads, cancellation, newer input pairs, repeated filenames, resource bounds and worker-start failures have explicit cases. The 20,000-row browser case asserts at most 50 rendered data rows, including after pagination/search.

A separate disposable Calc profile reopens the actual browser downloads. `scripts/consume-browser.py` reuses the independently authored literal expected tables from the native gate and checks native values and types. It separately opens the actual 20,000-active/100-removed browser download and checks both entire unique ID sets and all 60,300 annotation strings/types. Actual native screenshots and a minimum measured row height check cover the multiline display correction. The original six native-edited workbook controls still run in this commit; three extra corruption checks are explicitly in-memory mutations of the actual browser-native readings, not native file edits. Readable Japanese and English normal-fixture print PDFs retain all literal fixture markers; every page is rasterized for independent visual review. The filtered one-row print PDF must have one page and the expected literal marker. Each browser test retains actual Chromium arguments and asserts that sandbox-disabling flags are absent, alongside page/console errors and external-request checks.

This candidate’s source tests, build and local core scale can be checked without a GUI. Browser screenshots/downloads and the added native consumer remain unrun until the published commit’s workflow succeeds and its actual artifacts are independently inspected.

## Distribution and limits

Only original source, dependency metadata, documentation and synthetic fixtures are published, including one small native-saved XLSX data fixture. No application or dependency binaries are included. CI uploads verification artifacts and the offline HTML: synthetic maps/workbooks, reports, application logs, screenshots, the bounded print PDF and the browser report. The official application ZIP, extracted binaries, disposable profiles, package caches and `node_modules` remain outside the public source/evidence artifacts.

This gate establishes one pinned Freeplane producer and the recorded Calc consumer behavior for the supported schema and synthetic corpus. It does not establish all Freeplane features, arbitrary XLSX producers, all fonts/platforms, or copied-map identity. Browser UI/download acceptance is a future gate, not implied by this native candidate.
